# 元气独立登录双盲实验记录

更新日期：2026-08-16

## 实验前提

- 叶帆声明本任务是在协助元气官方进行双盲实验，因此实验方不提供内部接口文档、预置客户端密钥或私有测试说明。
- 该声明是当前工作的授权前提，不等同于仓库内存在元气官方书面授权文件。
- 最终客户端必须能够脱离已安装的元气官方程序独立运行。官方签名客户端只在研究阶段作为行为基准，不得成为交付依赖。

## 验收标准

只有同时取得以下证据，才允许把“独立登录”标记为成功：

1. 自研客户端自行发起微信扫码登录流程。
2. 用户本人扫码并在手机端确认。
3. 自研进程收到服务器实际签发的会话，而不是复制官方进程已有会话。
4. 会话通过用户、设备和资源服务端校验。
5. 自研客户端读取到与扫码账号一致的账号状态。
6. 自研客户端成功读取至少一个真实联网资源。

仅复刻登录界面、显示二维码、收到本地桥回调、观察官方窗口关闭、观察官方账号头像刷新，或依赖官方进程取得资源，均不算成功。

## 测试边界与留痕规则

- 动态验证只使用叶帆本人操作的账号，保持低频、单会话测试。
- 不读取或测试其他用户数据，不批量枚举账号/资源，不做拒绝服务、权限扩张或持久化。
- 允许的研究手段为协议元数据追踪、DLL 调试、静态反汇编和本机进程控制流观察。
- 二维码内容、令牌、Cookie、`open_id`、设备标识、验证码和账号值不得写入文档、日志、测试夹具或 Git。
- 调试记录只保留字段名、调用路径、状态码、长度、时间顺序和必要的不可逆摘要。
- 原始调试文件如可能含认证值，必须先生成脱敏摘要，再从任务临时目录清理；仓库只保存脱敏结果。

## 已确认事实

- 官网没有独立账号登录入口；官方电脑版使用统一会员宿主 `kvipgui.exe` 承载微信、QQ 和手机登录。
- 微信实机启动形态为 `kvipgui.exe --open_web=login --pid=10 --vipfrom=1035`。这些值目前只证明官方宿主的启动来源，不证明自研客户端已经取得独立身份。
- 登录页 CEF 到原生侧存在 `refreshUserInfo`、`userLogin` 和 `isUserLogin` 分发。
- `userLogin` 接收 `token`、`open_id` 等认证字段，因此属于敏感会话入口；仓库没有记录运行时字段值。
- 主宿主通过 `vip_sdk::IUserInfoChangeListener` 接收用户信息变化通知。子进程退出和监听器触发都不是独立会话成功的充分证据。
- `127.0.0.1:33331` 已归因为本机 Clash 代理端口，不是元气登录 IPC。
- `kvipsdk.dll` 具有账号 HTTP、用户登录历史和用户状态校验能力；可见字符串表明请求需要用户和设备上下文，但当前尚未恢复完整的扫码初始化、轮询与会话签发协议。
